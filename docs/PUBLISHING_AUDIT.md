# Аудит расширения публикаций — 10 октября 2026

## Реализовано и проверено локально

Финальная проверка после исправления OAuth-диагностики: 151 passed, 1 skipped (FFmpeg/ffprobe отсутствуют на Windows-хосте). Ruff F-check новых модулей пройден. В Dockerfile FFmpeg установлен, но Docker build и реальная обработка в контейнере здесь не запускались.

OAuth start больше не маскирует ошибки БД под отсутствующие credentials. Бот показывает конкретные недостающие параметры, публичный HTTPS base URL проверяется до создания flow. Добавлены inline-инструкция и локальный oauth-setup со скрытым вводом и атомарным сохранением env. Повторный general setup сохраняет PUBLIC_BASE_URL. Реальные App ID/Secret/Client key/secret отсутствуют в текущем env; подключение невозможно до регистрации приложений и настройки доступного HTTPS callback владельцем.

Исправление UndefinedColumn videos.remote_video_id: старая миграция 0002 ошибочно завершалась при наличии sources.platform и пропускала поля videos. Проверка теперь выполняется отдельно для каждого поля; миграция 0005 восстанавливает уже отмеченные как обновлённые частичные схемы. Локальный launcher выполняет upgrade head до запуска процессов и прекращает запуск при ошибке миграции. Regression tests проверяют обе исходные версии, повторный upgrade и сохранность файла/описания видео.

Расширена существующая Python-система: Telegram остаётся интерфейсом, Neon/PostgreSQL — постоянным хранилищем, Redis не добавлен как обязательная зависимость. Сохранены YouTube discovery, фильтры, источники, catalog, routes, schedules, jobs и уведомления.

PublishingDestination — единая проекция существующего SocialAccount, TelegramDestinationChat и AccountSchedule. Это сохраняет идентификаторы существующих аккаунтов, маршрутов и заданий. OAuthFlow, Event, Notification и Job используются повторно вместо создания параллельных таблиц с тем же назначением.

Добавлены Telegram-каналы/группы/форумные темы, native chat picker, проверка владельца/администратора и прав бота, сохранение chat_id, миграция групп, отдельное publishing_enabled, capabilities/status/last_verified_at. Включение требует проверки API; подключение не включает публикации автоматически.

Добавлены множественный выбор направлений в PostgreSQL FSM, подтверждение, independent jobs, дедупликация video/account, расписание/немедленная отправка/ожидание одобрения, настройки часового пояса и дней/лимитов/интервалов, приоритет, шаблоны описаний, история, ручной файл, отключение credentials.

Добавлены platform adapters, журнал попыток Telegram, sendVideo/sendDocument/sendPhoto/sendMessage/sendMediaGroup. Основной интерфейс ориентирован на видео/документ; фото/текст/альбом доступны адаптеру и не добавлены как отдельные пользовательские сценарии.

OAuth проверяет owner binding, срок и одноразовость state. Ранее Instagram scopes записывались как предоставленные без проверки: теперь читаются фактические permissions. TikTok сохраняет фактические scopes; refresh заменяет вращающийся refresh token. Поддержано чтение старых ключей Fernet при ротации. Browser callback возвращает безопасное сообщение и запрет кеширования; секреты provider error не сохраняются.

Миграция 0004 сохраняет существующие записи, добавляет только поля и новые вспомогательные таблицы. Проверены чистая установка, повторный upgrade и реконструированная старая таблица аккаунтов с сохранением ciphertext. Реальная PostgreSQL-база в этой сессии не изменялась.

## Проверено с реальной платформой

Не выполнялось. Нет предоставленных API credentials, доступного сервера, test media и разрешения на конкретную реальную публикацию. Кнопка «Проверить доступ» не публикует тестовое сообщение.

## Проверено только через mocks

Telegram API permissions, forum thread, adapter request arguments, lost-response recovery; Instagram/TikTok OAuth responses, actual scopes, replay/expiry/ownership. Mocks используются только в автоматизированных тестах, не в production adapters.

## Требует API credentials

BOT_TOKEN/OWNER_TELEGRAM_ID, серверный ENCRYPTION_KEY, production DATABASE_URL; для social OAuth — ключи Meta/TikTok, HTTPS PUBLIC_BASE_URL. Для Alembic/backup рекомендуется DATABASE_URL_UNPOOLED. Перед production проверяйте миграции на изолированной Neon branch с реальными схемой и данными.

## Требует App Review

Доступ Meta за пределами ролей приложения и необходимые права TikTok зависят от одобрения платформ. Консольные требования выполняются владельцем приложения; код не обходит проверку. PULL_FROM_URL требует проверенного домена.

## Ограничено официальным API

Direct Post TikTok отключён из-за назначения private owner-only utility. Черновик не равен опубликованному видео. YouTube Discovery предоставляет метаданные, а не разрешённый MP4. В Bot API нет универсальной идемпотентности sendVideo/чтения истории и перечисления всех форумных тем; неопределённые публикации требуют ручной сверки.

Прямые страницы документации Meta не удалось прочитать инструментом; проверена доступность официальной коллекции Meta, но production Instagram contract необходимо подтвердить live-тестом на профессиональном аккаунте.

## Не реализовано / не проверено

Развёртывание на сервере, реальный App Review, реальная проверка миграций на Neon/PostgreSQL, live публикации, автоматическое восстановление результата Telegram при потере ответа, независимая юридическая проверка прав, отдельный интерфейс выбора всех исторических тем Telegram. Direct Post не включён намеренно по правилам платформы.

Систему нельзя считать подтверждённой production-интеграцией до live acceptance A–H из исходного промпта. ZIP содержит код, тесты, deployment configuration и инструкции; секреты/БД/venv/медиа в него не включаются.
